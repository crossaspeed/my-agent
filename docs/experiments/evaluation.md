观察（可写进论文）：

1. **纯向量（hash）最高分普遍偏低**（0.04~0.27），说明词面哈希向量对中文语义的刻画能力弱 —— 这正是默认配置只用于「离线可跑」的原因。
2. **纯 BM25 返回条数少于 k**（如 #2、#7、#9），因为倒排命中的分块数不足；RRF 融合后仍能补足到 3 条，**召回覆盖率优于任一单路**。
3. `#10 NAT 的作用` 三路结果分歧最大（向量偏向 2/4/5，BM25 偏向 6/2/1），属正常现象：问题指向「作用」这一抽象描述，而语料中 NAT 仅在网络层文档的地址转换段落出现一次。该 case 适合作为「融合策略必要性」的论据。
4. 由于语料只有 6 个分块，top3 覆盖了全库的 50%，**P@3 无统计意义**，论文中应改为「在 200+ 分块语料上的人工标注评测」。

## 表 3 评分一致性（方法与样本）

演示库实际作答结果（1 名学生 / 5 题）：

| 题号 | 题型 | 得分 / 满分 | 评分方式 | 置信度 | 是否转人工 |
|---|---|---|---|---|---|
| 1 | single | 14.5 / 14.5 | 规则 | 1.00 | 否 |
| 2 | single | 0 / 21.5 | 规则 | 1.00 | 否 |
| 3 | multiple | 0 / 14.5 | 规则 | 1.00 | 否 |
| 4 | short | 1.5 / 35.0 | 智能体 | 0.98 | 否 |
| 5 | judge | 14.5 / 14.5 | 规则 | 1.00 | 否 |
| **总分** | | **30.5 / 100** | | | |

一致性机制（`grader_graph.consistency_check`）：

1. 首次评分（`LLM_TEMPERATURE_GRADE`）→ 第二次同模型 `temperature=0` 复评
2. 两分数差 ≤ 15%：取均值；> 15%：第三次评分取中位数；极差 > 30%：`needs_human=true`
3. 置信度 `1 - 极差/满分`，用于前端「低置信·待人工」标记

复现一致性评测的推荐做法（论文需要 N 份样本）：

```text
1. 准备 30 份人工标注答卷（同一题不同质量档：满分/部分/零分）
2. 对每份答卷调用 POST /attempts/{id}:submit，等 job 完成后读 report
3. 计算与人工分数的 ICC / Cohen's kappa / MAE
4. 统计 needs_human 比例（预期 5%-15%，过低说明阈值太松，过高说明模型不稳）
```

当前受限于 `mock` 模型与单份样本，**不给出 kappa 数值**；机制、阈值与统计口径已固化在代码与本文档中。
