# 当前指标速查（截至 2026-11-12）

> 一门课（计算机网络2 / course_id=8）、4 份 PPT、60 条人工标注 query（语料内 40 + 领域外 20）。
> 数据文件：`bench-course8-final-llm-t055.json`。所有数字均为实测，可由脚本复算。

## 六、场景化检索策略（重排 / 改写按检索点取舍，而不是全局开关）

三个智能体的检索 **query 来源完全不同**，所以“该不该重排/改写”不能用一套全局配置决定。
判断依据只有一条：**这条 query 是不是已经处在教材术语空间里。**

| 检索点 | query 实际内容 | 语言形态 | 重排 | 改写 | 理由 |
|---|---|---|---|---|---|
| 导学·首次（`tutor_graph:retrieve_node`） | 知识点名称拼接（`root_kp + 先修`） | 术语 | ❌ | ❌ | 知识点由课件抽取，已是术语；SSE 首字延迟优先 |
| 导学·追问（`tutor_graph:retrieve_followup`） | `学生原话 + 题干前 80 字` | **口语 / 跨语言** | ❌ | ✅ **开** | 系统中**唯一**由学生自由语言构成的入口 |
| 出题（`question_graph:retrieve_node`） | LLM 针对知识点生成的检索式（≤3 条/KP） | 术语 | ❌（改为按 KP 合并候选集后重排一次） | ❌ | 检索式**本身就是改写的产物**，再改是重复劳动 |
| 阅卷（`grader_graph:retrieve_rubric`） | `题干 + 解析`（前 300 字） | 术语（最典型） | ✅ | ❌ | 题干由课件片段生成、解析含原文措辞，属字面类 |

### 为什么阅卷开改写是净损失（实测）

拿 15 条字面类查询（形态最接近“题干+解析”）对比改写前后：

- **Hit@1 一条都没变**（15/15）；
- `relevance` 均值 **−0.0071**，6/15 条下降，最差一条 `什么是封装成帧` 从 **1.000 → 0.667**
  —— 改写模型给它补了“的定义”三个字，反而稀释了与原文的字面重合；
- 代价是每题 **+1.1 s**。

而跨语言类同样一批数据：`relevance` 平均 **+0.25**（0.446→0.833、0.538→1.000），Hit@1 8/10→9/10。
**改写的价值完全集中在“语言/术语不匹配”的场景**，对已经在术语空间内的 query 只是稀释。

### 延迟代价（按瓶颈环节核算）

| 检索点 | 规模 | 开改写的额外开销 |
|---|---|---|
| 出题 | 20 KP × 3 query = **60 次串行** | +60 × 1.15 s ≈ **+69 s**（出题本身仅 22 s，会变 4 倍） |
| 阅卷 | 单卷 N 题，并发 4 | +⌈N/4⌉ × 1.15 s（5 题约 +2 s，20 题约 +6 s） |
| 导学·追问 | 1 次 | +1.15 s（**唯一值得付这个代价的地方**） |

### 实机验证（不是推断）

同一时间窗内跑三个场景，`llm_calls` 表的场景分布直接证明策略生效：

```
09:38:39-09:38:59  导学：tutor_diagnose → tutor → query_rewrite(1148ms) → tutor
09:39:10-09:39:27  出题：question_plan → rerank×2 → question_gen×2     ← 无改写
09:40:22-09:40:29  阅卷：grader_extract → rerank → grader_subjective×2  ← 无改写
```

`query_rewritten` 日志在整个窗口只出现 **1 次**，正是导学追问那句
「网络为什么会堵车 请结合课程材料…」→ 改写为「网络拥塞原因及三次握手而非两次握手的含义与作用」。

护栏测试：`backend/tests/unit/test_retrieval_policy.py` 用源码断言固定这四条策略，
防止后续重构把 `use_rewrite=True` 误加到出题或阅卷上。

## 七、已知局限

- 单门课、60 条样本：每个百分点约等于 0.4 条 query，**不要过度解读 1~2 条的差异**；
- 参数（分块 900/1200、阈值 0.55）是在这批数据上校准的，换语料需重扫；
- 检索指标只反映“找材料”的能力，**不反映出题质量与讲解正确性**；
- 单条 2 s 主要花在 LLM 重排，导学链路（SSE）当前不开重排；
- 改写只在导学追问启用（约 +1.1 s 首字延迟），换来口语 Hit@3 0.867→1.000；
  但它会抬高跑题问题的相关度（误纳 15%→30%），因此**不能开在有门禁的出题链路上**。
